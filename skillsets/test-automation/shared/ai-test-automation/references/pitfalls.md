# Pitfalls and the check for each

| Failure learned | Required check before adoption |
|---|---|
| Tests written to pass: expectations copied from code, loose matchers, mocks that pre-filter data, green as the goal. | Specific asserts per `expected` line; `mockPolicy: mixed-source`; reject vague expected text; positive/negative/regression per criterion; red-on-base proof. |
| Scenarios drafted from current source code bias tests toward green. | `check-scenarios` rejects implementation citations; design from the ticket only. |
| New feature tests pass before the product change lands. | Supply `--base-results` to `judge`; `passes without the change` blocks storage. |
| A failing test is "fixed" by weakening expected results. | Use `status: bug` + `bugKey`; keep the scenario red and block only that ticket's PRs. |
| Unhandled mock calls return empty and accidentally satisfy empty-state tests. | Fail the test on every unhandled call with its method and URL. This complements, and never replaces, mixed-source intent. |
| A mock accepts a write the scenario never declared, so a wrong POST/PATCH body goes green. | Mock write policy: refuse every undeclared write by method, path and body; parse JSON only for `application/json`; refuse multipart without a boundary; route every spec-registered route through the policy so a later overlay cannot serve a forbidden write. Prove with a refusal test that asserts the policy's own message and is red on a mock without the policy. |
| A refusal test passes through `test.fail()`, so any failure counts as success. | Assert the policy's own refusal message; `test.fail`, `test.skip`, `test.fixme`, `test.only`, `test.slow`, `test.setTimeout`, `waitForTimeout` and `retries` above zero are rejected by `check-scenarios --source`; a per-test `{ timeout: N }` option is not detected, so review it by hand. |
| `toHaveText`, `getByText` or `exact: true` pass while CSS `text-transform` shows different letter case. | Assert rendered text with `{ useInnerText: true }` or `innerText()` plus `toHaveCSS('text-transform', …)`; a unit or jsdom runner cannot carry a visual line. |
| `toBeVisible()` passes while colour, font or icon is wrong. | Per expected visual, assert computed style or the named icon identity, then set each value wrong on purpose and keep the red run. Expected values come from the design reference, never from application source or the running app. |
| Visual instructions soften into conditional, hedged phrasing and agents skip them. | The pack drift test rejects hedge phrases in every skill and reference; each rule is stated as a requirement. |
| Provider task rules only point at a skill, so the visual and mock rules never load. | Every provider surface embeds the same core block; the pack drift test compares them byte for byte. |
| An explicit Deny on a broad group overrides a narrower group's Allow. | Inspect effective permission for the exact service identity after inheritance is broken; assert read allowed, reviewed PR allowed, direct bypass denied. |
| A required PR policy can block agent direct push unless it can bypass. | Exercise the guarded agent route and require it to create/reuse a PR; never infer direct-push permission from repo write access. |
| Draft PRs may not trigger build validation. | Open a ready-for-review probe PR and confirm the exact required check starts; draft state is not evidence. |
| First cross-repo pipeline run needs repository authorization. | Run a checkout-only authorization preflight and confirm QA repo ref is resolved before relying on its files. |
| Test steps must run without secrets. | Print the test job's effective env names/scopes in a safe audit and assert no board/upload/deploy token is present; checkout credentials are not persisted. |
| PR-controlled Allure/report code can rewrite verdict artifacts and redirect trusted board writes to arbitrary work items. | Keep PR checkout, npm install, tests and Allure rendering read-only with checkout credentials disabled; upload Allure assets separately. In the trusted publisher, load QA default-branch code, download the trusted plan and raw runner results separately, recompute the verdict, verify plan hash/head/run identity and scenario/work-item membership, then post only recomputed rows. Prove an out-of-plan forged PASS posts nothing and an in-plan forged PASS loses to raw-result recomputation. Raw results remain untrusted and can spoof outcomes only for planned scenarios. Run the static CI-template security test for both providers. |
| PR title/body/branch text can name an unrelated but valid ticket and redirect trusted plan/publisher writes. | Planner uses `linkedItemsForChange(change)` with the trusted board/forge token and plans only returned associations. Treat textual IDs and `--item` values as hints; report unmatched ones as `named but not linked` and ensure they cannot reach any write method. Probe with a malicious PR naming a valid unassociated ticket; assert the legitimately linked ticket remains planned and no comment is posted to the decoy. |
| Branch copies of acceptance tests can be edited to spoof authority. | Overlay QA-owned scenarios/tests before running, log ignored copied paths, and assert the installed digest equals QA source. |
| Regression membership comes from base, not head or current ticket association. | Remove/relabel a base scenario and unlink its ticket in a probe; assert it remains in `scenarioIds`, `regressionIds`, the verdict and report, while it is absent from board write targets unless its item is independently associated. |
| GitHub issue numbers collide across repositories. | Return a closing reference to `otherrepo#12` while `config.repo` is `acme/api`; assert it is listed under `crossRepo` and no GET/POST is sent to `/repos/acme/api/issues/12`. |
| Static “test exists” checks are spoofable by comments, strings, dead code, `#if false` and `Skip=`. | `lang-tokenize.mjs` blanks comment/string bodies per language (escape-aware); `tokenizer-spoof.test.mjs` is the corpus. Run compile, discovery and execution checks too. |
| A scenario looks covered because its ID sits in a comment, a string or a skipped test of a source file. | `check-scenarios --source` counts a scenario as bound only when a runnable test title, `scenario_id` label or `DisplayName` carries the whole ID; probe with the tag in a comment, a string, a test body, a skipped test and a longer ID. |
| A gate check is refactored away and the gate keeps passing bad runs. | `judge` and `check-scenarios` run the canaries first (`SANITY_CANARY_FAILED`); every new rule ships the input that must fail it, and a test proves the canary notices a gate that always passes. |
| A run aimed at a deployed URL hits an origin nobody declared. | `qa test --base-url` refuses with `TARGET_NOT_ALLOWED` unless the URL is loopback or its origin is in `environments.<name>.origins`; probe a mislabelled `local`, a lookalike host and an unknown environment. |
| A deployed run uses a personal or admin account, leaks a secret, passes with a missing prerequisite or leaves records behind. | Identities only from declared CI variables with a deny list, secrets never printed, preflights give BLOCKED (exit 2), and a cleanup ledger must be proven gone; probe each refusal and grep every output and file for planted secrets. Environment checks apply only to deployed targets. |
| A skip hides behind an import alias (`from pytest import skip`, `import pytest as pt`, `from unittest import skip as later`). | `--source` rejects the alias when it is called or used as a decorator and accepts a local helper or plain reference of the same name; destructured, wrapped and assigned aliases need a parser, so review them by hand. |
| Skipped tests are not executed. | Feed JUnit skipped, TRX NotExecuted, Playwright skipped and Allure skipped fixtures; all must remain non-VERIFIED. |
| Manual/awaiting exceptions must be judged the same by storage and gate. | Send identical valid/invalid fixtures through both consumers and compare verdict plus reason. |
| Report-only changes must keep verdicts byte-identical. | Run reference-judge golden fixture before and after report changes and compare canonical verdict bytes. |
| A failed attachment still blocks. | Inject upload HTTP failure, missing token, absent returned URL and failed relation; verify no success verdict or transition. |
| Repeated CLI args must accumulate. | Invoke repeated `--item`, `--source` and `--file` and assert all values are retained in order. |
| Tracker comments must be idempotent by commit plus content, not commit alone. | Replay identical marker twice and verify one comment; change content on the same commit and verify a different full hash marker. |
| PR linking or card movement can race with a stale board revision. | Change revision between read and write; expect conflict and no retry/move until re-plan. |
| Webhook deliveries can be forged or duplicated. | Invalid signature and repeated delivery ID must enqueue/mutate nothing; valid raw-body signature is accepted once. |

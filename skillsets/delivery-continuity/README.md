# Delivery continuity

These provider-neutral skills keep authorized work moving through its requested
outcome while preserving security and user-owned decisions. `finish-the-job`
owns completion, recovery, consumer checks, and distribution;
`meaningful-tests` owns per-goal evidence and workflow verdicts.

The standing delivery contract is rendered into all four provider homes. Board
evidence remains required for conclusions that depend on a configured board or
ticket acceptance; missing unrelated tooling is not a universal stop condition.
Skills apply at their actual task and runtime boundary. Existing authorization
persists, and a generic skill confirmation does not require asking again.

Publish only the intended lessons with the existing backup and local-edit
protection:

```sh
node scripts/publish.mjs --check --lesson finish-the-job --lesson meaningful-tests
node scripts/publish.mjs --lesson finish-the-job --lesson meaningful-tests
```

Repeat `--lesson` to select multiple lessons. Unknown or missing names refuse
before publication. An in-place edit still requires reconciliation or explicit
replacement with a backup. Remote targets use the existing measured target
configuration; publication does not install a repository on the target.

After installation, compare the intended copies, refresh the skill index, and
run its check. Index refresh preserves invocation policies. Existing sessions
may cache old directives; use a supported idle-session refresh and record the
remaining active-session boundary without interrupting unrelated work.

The native Stop checks provide a bounded correction, not proof of completion
or a model-wide guarantee. Compact field/value evidence and Markdown labels
retain their meaning; empty fields and quoted examples do not constitute a
packet. Only the measured user outcome justifies its verdict.

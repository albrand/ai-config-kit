# Library and directive audit — 2026-08-21

Proposed by Hermes, running on its own machine so the review is independent
and costs the local providers nothing. **Nothing here has been applied.**
Read it, argue with it, then edit the lessons yourself.

MERGE: none. `bb-plugin-authoring` and `bb-sdk-traps` are adjacent but distinct: one diagnoses plugin lifecycle failures; the other documents deceptive SDK semantics. Combining them would broaden matching and load more irrelevant material.

RETIRE: `CLAUDE.md — Security-first defaults` should retire “dependencies or build/config files” as an unconditional trigger for loading `SECURITY_AND_PENTEST.md` and `QUALITY_GATES.md`. Ordinary package metadata, formatter settings, and benign build configuration do not inherently require the full security profile. Keep the trigger for auth, access control, secrets, crypto, external input, outbound requests, executable build hooks, dependency-source changes, and other trust-boundary changes. With Claude at 3.6M weighted tokens/turn and 99% cache share, avoiding unnecessary policy loads is measurable.

CONFLICT: `CLAUDE.md — Operating framework` says “load only the profile the task needs,” while `CLAUDE.md — Security-first defaults` requires the security profile whenever a change touches any “dependencies or build/config files.” The latter converts a risk-based profile choice into a filename-category mandate, even when no security boundary changes.

GAP: none. The dominant `git`, `grep`, `sed`, and no-tool activity does not establish a missing workflow; `CLAUDE.md — Default process`, `Reality sync`, and existing validation directives already cover repository inspection. Subprocess invisibility prevents provider-absence conclusions.

SHARPEN: none. The supplied skill descriptions have concrete task-language triggers. `orchestrator-lessons` still appears broad in the inventory, but its narrowing is already applied and must not be proposed again.

OPTIMIZATION | Narrow CLAUDE.md Security-first defaults so ordinary dependency metadata and benign build/config edits do not automatically load the full security profile; retain triggers for executable supply-chain and trust-boundary changes | reduces unnecessary security-policy context on routine Claude coding turns while preserving high-risk coverage

# Library and directive audit — 2026-08-18

Proposed by Hermes, running on its own machine so the review is independent
and costs the local providers nothing. **Nothing here has been applied.**
Read it, argue with it, then edit the lessons yourself.

MERGE: none.

RETIRE: `CLAUDE.md — Ecosystem terraform commands` and `CLAUDE.md — PR review command` are task-specific operating manuals embedded in every Claude turn. Their procedures already point to on-demand guides/frameworks; retain only one-line triggers and move the detailed routing, preflight, mutation, and review rules to those existing sources. With 99% cache share, these non-universal blocks impose cost even on the 12,231 no-tool turns.

CONFLICT: `CLAUDE.md — Sub-agent lifecycle freshness` says a completed agent should be captured, closed, and replaced with “a fresh agent rather than reuse stale context.” `reviewing-with-an-agent` says “a re-review must continue the original conversation.” The review rule needs an explicit exception: preserve or resume the original reviewer thread while the same review remains active; use a fresh agent only after that review lifecycle ends. Otherwise re-review loses prior findings and repays context acquisition.

GAP: process-wait and host-liveness polling. The 109 `cmd:sleep` turns and 194 `cmd:uptime` turns show repeated activity not covered by `headless-linux-agents`, whose description triggers only after concrete sandbox, installation, login, or daemon failures. The attribution is too coarse to justify adding a lesson yet; first distinguish intentional heartbeats from wasteful polling.

SHARPEN: none.

OPTIMIZATION | Reduce `CLAUDE.md — Ecosystem terraform commands` and `CLAUDE.md — PR review command` to one-line on-demand triggers | Removes task-specific procedural text from every cached Claude turn  
OPTIMIZATION | Add a same-review exception to `CLAUDE.md — Sub-agent lifecycle freshness` for `reviewing-with-an-agent` continuation | Avoids fresh-reviewer context reconstruction and duplicate review work

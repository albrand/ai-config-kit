## Sync and duplication findings

- `scripts/typed-decisions-sync.py` is the only in-repo synchronizer that
  targets all five global instruction files. It owns the `typed-decisions`
  block and updates it from `GLOBAL_BLOCK`.
- No kit generator or sync script for the complete Claude, Codex, OpenCode, or
  bb home files was found. Their remaining content is hand-maintained; the
  repeated kit rules are manual mirrors, not generated copies.
- Exact same-marker duplicates across the four live homes are: `delivery-first`
  (all four), `token-efficient-orchestration` (all four), and
  `typed-decisions` (all four). `ai-config-kit-scope` is duplicated in Codex
  and OpenCode; `no-ai-signatures` and `security-first-defaults` are duplicated
  in Codex, OpenCode, and bb.
- Therefore Claude + bb currently repeat three identical marked blocks;
  Codex + bb repeat six. Testing-claim, finish-the-job, worktree, feature-flag,
  and email policies also overlap in meaning, but are not all byte-identical.
- `bb guide agent-configuration` confirms that `~/.bb/AGENTS.md` is appended
  to every provider-backed thread. Codex also reads its native global
  `~/.codex/AGENTS.md`; its requested context is both files. Claude's native
  `~/.claude/CLAUDE.md` and the bb data-dir file are likewise both present in
  its provider-backed context.

Some project/provider policies have no shared global counterpart and remain in
the relevant overlay: Codex board/OpenCode/Replit routing; OpenCode executor and
session lease; bb provider-neutral login, Hermes, and child routing. Claude has
no additional provider-specific policy in its current home.

The renderer `scripts/render-standing-homes.py` combines these checked-in
sources and writes reviewable proposals under `proposals/card21/rendered-homes`.
Its `--install` mode is intentionally not run in this task. It backs up each
live home before replacement. The only existing sync (`typed-decisions-sync.py`)
now emits the same compact typed block used by those proposals.

After compaction, each provider file repeats only the short hard-rule block and
typed-decisions block required by existing homes; general process, delivery,
testing, and token sections live once in the bb-injected baseline. Thus the
identical `delivery-first` and `token-efficient-orchestration` blocks no longer
repeat in Claude/Codex/OpenCode files, while the named hard prohibitions remain
present in every proposal.
